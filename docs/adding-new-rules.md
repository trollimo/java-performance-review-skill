# Adding New Performance Rules

Version 1.0

Этот документ описывает единый шаблон добавления новых правил.

---

## Алгоритм

1. Найти технологию.

Например

Spring

Kafka

PostgreSQL

Java

или создать новую папку.

---

2. Определить тему.

Например

spring/cache.md

spring/webclient.md

postgresql/indexes.md

---

3. Если файла нет —

создать его.

---

4. Каждое правило получает уникальный ID.

Пример

SPR-101

PG-203

JAVA-315

## Требования

Каждое правило

✔ объясняет причину

✔ объясняет последствия

✔ предлагает исправление

✔ содержит Severity

✔ содержит Confidence

✔ содержит Expected Improvement

✔ имеет уникальный ID

---

## Не допускается

- дублировать существующие правила

- делать правило без объяснения

- использовать расплывчатые формулировки

- использовать слово "может" без пояснения

---

## Если найдено новое семейство ошибок

Создать новый markdown-файл.

Не увеличивать существующие файлы бесконечно.

Оптимальный размер файла

300–1200 строк.

---

- Related Rules

- Checklist

## Индекс правил

После добавления или изменения правила перегенерировать индексы:

```
python3 scripts/build_index.py
```

Проверка актуальности (для CI и pre-commit):

```
python3 scripts/build_index.py --check
```

Индексы читает агент: `rules/INDEX.md` и `rules/<tech>/INDEX.md`.
Из блока правила берутся

- ID из строки `# <PREFIX>-<NUMBER>`
- название из секции `## Название`
- severity из строки после `Severity`
- grep-подсказка из секции `### Grep` (необязательная)

Формат секции `### Grep` (перед секцией `### Что искать`)

```
### Grep

`*.{py,java,kt}` :: `requests\.(get|post)\(`

---
```

Правила записи

- glob: `*.py`, `*.{java,kt}`, `Dockerfile*`, `*compose*.{yml,yaml}`, `*.conf`; фигурные скобки допустимы
- regex: синтаксис ripgrep, без lookahead/lookbehind и обратных ссылок, без символа обратной кавычки
- многострочный regex допустим (`\n`, `(?s)`), но использовать его только когда одной строкой не выразить
- флаги `(?i)` и `(?m)` в начале regex допустимы
- проверка отсутствия: вторая строка `Нет: `regex`` без пустой строки между ними

```
### Grep

`*.conf` :: `\bserver\s*\{`
Нет: `\bgzip\s+on`

---
```

Правило подходит для файлов, где первый regex найден, а второй нет.

Подсказка ищет кандидатов, а не доказывает проблему, поэтому небольшая избыточность допустима.
Но подсказка, срабатывающая почти в каждом файле, хуже её отсутствия.
Для чисто дизайнерских правил и правил про измерения секцию не писать.

Проверка

```
python3 scripts/check_grep.py                    # синтаксис всех подсказок
python3 scripts/check_grep.py <репозиторий>      # шум на реальном коде
python3 scripts/check_grep.py --rules ID1,ID2    # только указанные правила
```

Подсказка, давшая совпадения больше чем в 15 файлах, помечается как шумная: её нужно сузить.
Новое правило проверить на реальном проекте с известной проблемой.
