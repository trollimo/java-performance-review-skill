# AI Maintainer Guide

Этот документ предназначен для ИИ, который будет развивать данный репозиторий.

---

## Цель

Сделать репозиторий максимально полной базой знаний по поиску проблем производительности Java Enterprise систем.

Не изменять существующие правила без необходимости.

Предпочитать добавление новых.

---

## При каждой доработке

1.

Просканировать весь репозиторий.

---

2.

Найти

- пустые файлы

- почти пустые файлы

- незаполненные разделы

---

3.

Заполнить их.

---

4.

Проверить

нет ли технологий,

для которых отсутствуют правила.

Например

Redis

Oracle

MongoDB

RabbitMQ

Elasticsearch

gRPC

Netty

R2DBC

Reactor

Virtual Threads

Micrometer

Prometheus

---

5.

Если технология отсутствует —

создать новую папку.

---

6.

Для каждой новой технологии

создать минимум

20 правил.

---

7.

Использовать шаблон

из

docs/adding-new-rules.md

---

8.

Не изменять ID существующих правил.

---

9.

Не удалять правила.

Допускается только

Deprecated.

---

10.

Поддерживать размер файла

не более

1200 строк.

При превышении —

разделить файл.

---

11.

У каждого правила должна быть секция `### Grep`
(формат — в docs/adding-new-rules.md, раздел «Индекс правил»).
Без неё агент-ревьюер не найдёт правило механически.
Исключение — чисто дизайнерские правила и правила про измерения:
подсказку для них не выдумывать.

---

12.

После правок обязательно

python3 scripts/build_index.py

python3 scripts/check_grep.py

python3 scripts/check_grep.py <путь к реальному репозиторию>

Первая команда пересобирает индексы, вторая проверяет синтаксис подсказок,
третья показывает шум на реальном коде.
Правило, которое срабатывает больше чем в 15 файлах, сузить.
Индексы вручную не править.

---

13.

Новые правила проверять на реальном проекте:
подсказка должна срабатывать на известной проблеме и молчать на чистом коде.

---

14.

Правила не привязаны только к Java.
Каталоги: language (java, kotlin, python), framework (spring, django),
data (sql, postgres, hibernate, jooq, liquibase, migrations),
infra (nginx, docker, redis, kafka),
general — сквозные правила для любого backend-кода.
Инфраструктурные проблемы (nginx без gzip, контейнер без лимитов, Redis без maxmemory)
находить так же важно, как проблемы кода.

## После каждой серии изменений

Проверить

- нет ли дублирования

- нет ли одинаковых правил

- есть ли Related Rules

- есть ли Critical List

---

## Главная цель

Каждая новая версия репозитория должна содержать больше практических знаний, чем предыдущая.
